# Quranic Arabic Flashcards — Auth & Multi-User Addon
**Version:** 2.0  
**Date:** April 2026  
**Status:** Planning  
**Builds on:** v1.0 POC (single HTML file, localStorage)

---

## Overview

This document covers the additions required to take the Quranic Arabic Flashcard app from a single-user browser POC to a hosted, multi-user application. The approach is deliberately minimal — the existing flashcard HTML/JS/CSS is unchanged in structure. We are adding a thin auth layer (PocketBase) and swapping `localStorage` for server-side persistence.

No new frontend framework. No build step. Still a single HTML file.

---

## Goals

- Allow multiple users to have independent accounts and card progress
- Persist progress across devices and browsers (not just localStorage)
- Keep the deployment simple enough to run on a single cheap VPS
- Keep the codebase entirely in version control — no manual admin UI clicks required
- Get from zero to hosted in under 2 hours

---

## What Is Not Changing

- The flashcard UI — card flip, answer buttons, progress bar, word list, stats screen
- The SRS algorithm (SM-2 variant)
- The word list (300 words from CSV)
- The session structure (10 new + 5 review)
- The single HTML file delivery model

---

## Stack Addition: PocketBase

PocketBase is a single Go binary that provides:

- Email/password authentication with JWT tokens
- SQLite-backed database with a REST API
- An admin dashboard at `/_/`
- A JS migrations system — schema defined in code, committed to version control
- File storage (not needed here, but available)

It runs as one process on the VPS alongside Nginx. No Docker required, though Docker is fine if preferred.

**Why PocketBase over FastAPI + Postgres:**

| Concern | PocketBase | FastAPI + Postgres |
|---|---|---|
| Setup time | ~30 min | ~2–3 hours |
| Processes to manage | 1 (+ nginx) | 3 (api + db + nginx) |
| Schema in code | Yes (JS migrations) | Yes (Alembic) |
| Admin UI | Built-in | Build yourself |
| Backup | `cp pb_data/data.db` | `pg_dump` |
| Right scale for this app | Yes | Overkill |

## PocketBase Schema

### Collections

**`users`** — handled automatically by PocketBase's built-in auth system. No migration needed. Fields provided out of the box: `id`, `email`, `password` (hashed), `created`, `updated`, `verified`.

**`card_progress`** — one record per user per word. Stores the full SRS state.

| Field | Type | Notes |
|---|---|---|
| `id` | text | auto-generated by PocketBase |
| `user` | relation → users | required, links progress to an account |
| `word_id` | number | 1–300, matches the word list index |
| `interval` | number | days until next review (float) |
| `ease` | number | ease factor, starts at 2.5 |
| `due` | date | datetime when card is next due |
| `reps` | number | total times this card has been answered |
| `created` | date | auto |
| `updated` | date | auto |

**Access rules on `card_progress`:**

```
List/View:   @request.auth.id = user.id
Create:      @request.auth.id != ""
Update:      @request.auth.id = user.id
Delete:      @request.auth.id = user.id
```

Users can only see and modify their own records. No admin-level leaking.

## Migration Files

All schema is defined in JS migration files committed to version control. PocketBase runs any unapplied migration automatically on startup — no manual steps after the first deploy.

### `pb_migrations/001_create_card_progress.js`

```js
/// <reference path="../pb_data/types.d.ts" />
migrate((app) => {
  const collection = new Collection({
    name: "card_progress",
    type: "base",
    listRule:   "@request.auth.id = user.id",
    viewRule:   "@request.auth.id = user.id",
    createRule: "@request.auth.id != \"\"",
    updateRule: "@request.auth.id = user.id",
    deleteRule: "@request.auth.id = user.id",
    fields: [
      {
        name: "user",
        type: "relation",
        required: true,
        options: { collectionId: "_pb_users_auth_", cascadeDelete: true }
      },
      { name: "word_id",  type: "number", required: true },
      { name: "interval", type: "number", required: false },
      { name: "ease",     type: "number", required: false },
      { name: "due",      type: "date",   required: false },
      { name: "reps",     type: "number", required: false }
    ]
  })
  app.save(collection)
}, (app) => {
  const collection = app.findCollectionByNameOrId("card_progress")
  app.delete(collection)
})
```

### `pb_migrations/002_create_superuser.js`

Creates the initial admin account from environment variables — no hardcoded credentials in the repo.

```js
/// <reference path="../pb_data/types.d.ts" />
migrate((app) => {
  const superusers = app.findCollectionByNameOrId("_superusers")
  const record = new Record(superusers)
  record.set("email",    $os.getenv("PB_ADMIN_EMAIL"))
  record.set("password", $os.getenv("PB_ADMIN_PASSWORD"))
  app.save(record)
}, (app) => {
  try {
    const record = app.findAuthRecordByEmail("_superusers", $os.getenv("PB_ADMIN_EMAIL"))
    app.delete(record)
  } catch {}
})
```

Set these before first run:
```bash
export PB_ADMIN_EMAIL=your@email.com
export PB_ADMIN_PASSWORD=a-strong-password-here
```

### Auth Logic (~30 lines)

```js
const pb = new PocketBase('https://yourdomain.com')

async function login() {
  try {
    await pb.collection('users').authWithPassword(
      document.getElementById('auth-email').value,
      document.getElementById('auth-password').value
    )
    await loadProgress()
    showScreen('study-screen')
  } catch(e) {
    document.getElementById('auth-error').textContent = 'Invalid email or password.'
  }
}

async function register() {
  const email    = document.getElementById('auth-email').value
  const password = document.getElementById('auth-password').value
  try {
    await pb.collection('users').create({ email, password, passwordConfirm: password })
    await pb.collection('users').authWithPassword(email, password)
    showScreen('study-screen')
  } catch(e) {
    document.getElementById('auth-error').textContent = 'Could not create account.'
  }
}

function logout() {
  pb.authStore.clear()
  showScreen('login-screen')
}

// On load: if already authenticated, go straight to study
if (pb.authStore.isValid) {
  loadProgress().then(() => showScreen('study-screen'))
} else {
  showScreen('login-screen')
}
```

### Replacing localStorage with PocketBase (~30 lines)

The `saveData()` and initial load functions are the only things that change. The SRS logic, session building, and UI functions are completely untouched.

```js
// BEFORE — localStorage
function saveData() {
  localStorage.setItem('qfc2_cards', JSON.stringify(cards))
  localStorage.setItem('qfc2_stats', JSON.stringify(stats))
}

// AFTER — PocketBase
async function saveData() {
  const userId = pb.authStore.record.id

  // Upsert each modified card
  for (const card of cards) {
    const existing = await pb.collection('card_progress').getFirstListItem(
      `user="${userId}" && word_id=${card.id}`
    ).catch(() => null)

    const payload = {
      user: userId, word_id: card.id,
      interval: card.interval, ease: card.ease,
      due: card.due ? new Date(card.due).toISOString() : null,
      reps: card.reps
    }

    if (existing) {
      await pb.collection('card_progress').update(existing.id, payload)
    } else {
      await pb.collection('card_progress').create(payload)
    }
  }

  // Stats stored in localStorage still (per-device is fine for streak/counts)
  localStorage.setItem('qfc2_stats', JSON.stringify(stats))
}

async function loadProgress() {
  const userId = pb.authStore.record.id
  const records = await pb.collection('card_progress').getFullList({
    filter: `user="${userId}"`
  })

  // Merge server state into local cards array
  records.forEach(r => {
    const card = cards.find(c => c.id === r.word_id)
    if (card) {
      card.interval = r.interval || 0
      card.ease     = r.ease     || 2.5
      card.due      = r.due ? new Date(r.due).getTime() : 0
      card.reps     = r.reps     || 0
    }
  })
}
```

> **Note on stats:** The streak counter is kept in localStorage per-device. This is intentional — streak is a motivational tool and per-device is fine. Global stats (total studied, easy rate) could be derived from PocketBase records in a future version.

## Deployment Guide

### 1. Provision the VPS

```bash
# On Hetzner — create CX11, Ubuntu 24.04
# SSH in as root, then create a non-root user
adduser deploy
usermod -aG sudo deploy
su - deploy
```

### 2. Install Nginx and Certbot

```bash
sudo apt update && sudo apt install -y nginx certbot python3-certbot-nginx
```

### 3. Download PocketBase

```bash
mkdir -p /opt/flashcards && cd /opt/flashcards

# Check https://github.com/pocketbase/pocketbase/releases for latest version
wget https://github.com/pocketbase/pocketbase/releases/download/vX.X.X/pocketbase_X.X.X_linux_amd64.zip
unzip pocketbase_*.zip
chmod +x pocketbase
rm pocketbase_*.zip
```

### 4. Add Migration Files

```bash
mkdir pb_migrations
# Copy 001_create_card_progress.js and 002_create_superuser.js here
# (from your version-controlled repo)
```

### 5. Copy the App

```bash
mkdir public
# Copy your updated index.html here
# Make sure the PocketBase URL in the JS points to your domain
```

### 6. Create a Systemd Service

This keeps PocketBase running and restarts it on crash or reboot.

```bash
sudo nano /etc/systemd/system/flashcards.service
```

```ini
[Unit]
Description=Quranic Flashcards - PocketBase
After=network.target

[Service]
Type=simple
User=deploy
WorkingDirectory=/opt/flashcards
ExecStart=/opt/flashcards/pocketbase serve --http="127.0.0.1:8090"
Restart=always
RestartSec=5
Environment=PB_ADMIN_EMAIL=your@email.com
Environment=PB_ADMIN_PASSWORD=your-strong-password

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable flashcards
sudo systemctl start flashcards

# Verify it's running
sudo systemctl status flashcards
```

### 7. Configure Nginx

```bash
sudo nano /etc/nginx/sites-available/flashcards
```

```nginx
server {
    listen 80;
    server_name yourdomain.com;

    # Serve the static HTML app
    location / {
        root /opt/flashcards/public;
        try_files $uri $uri/ /index.html;
    }

    # Proxy PocketBase API and admin dashboard
    location /api/ {
        proxy_pass         http://127.0.0.1:8090;
        proxy_set_header   Host $host;
        proxy_set_header   X-Real-IP $remote_addr;
        proxy_set_header   X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
    }

    location /_/ {
        proxy_pass         http://127.0.0.1:8090;
        proxy_set_header   Host $host;
        proxy_set_header   X-Real-IP $remote_addr;
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/flashcards /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

### 8. Enable SSL

```bash
sudo certbot --nginx -d yourdomain.com
# Follow prompts — Certbot edits the nginx config automatically
# Auto-renewal is set up by Certbot by default
```

### 9. First Run — Migrations Execute Automatically

On first start, PocketBase runs all unapplied migrations in `pb_migrations/` in filename order. The `card_progress` collection and the superuser account are both created automatically.

```bash
# Verify migrations ran
sudo systemctl restart flashcards
sudo journalctl -u flashcards -f
# Look for: "Running migration 001_create_card_progress.js ✓"
```

### 10. Verify Everything

```bash
# App loads
curl https://yourdomain.com

# PocketBase API responds
curl https://yourdomain.com/api/health

# Admin dashboard accessible at
# https://yourdomain.com/_/
```

## Backups

The entire database is a single SQLite file. Back it up with a cron job:

```bash
# /etc/cron.daily/flashcards-backup
#!/bin/bash
DATE=$(date +%Y-%m-%d)
cp /opt/flashcards/pb_data/data.db /opt/backups/flashcards-$DATE.db
# Keep last 30 days
find /opt/backups -name "flashcards-*.db" -mtime +30 -delete
```

```bash
sudo mkdir -p /opt/backups
sudo chmod +x /etc/cron.daily/flashcards-backup
```

To restore: stop PocketBase, replace `data.db`, restart.

## User Management

Once deployed, manage users via the PocketBase admin dashboard at `https://yourdomain.com/_/`. From there you can:

- View all registered users
- Manually create accounts (useful for inviting the first few friends without self-registration)
- Disable self-registration if you want invite-only (toggle in the `users` collection auth settings)
- View card_progress records per user
- Delete accounts

---

## Invite-Only Mode (Optional)

If you don't want open registration — just your group of friends — disable public registration in PocketBase:

1. Go to `/_/` → Collections → users → Auth settings
2. Uncheck "Allow email/password registration"
3. Save

Then create accounts manually for each person from the admin dashboard. They can change their password after first login.

Alternatively, keep registration open but limit it by adding an email domain rule in the collection's `createRule`:

```
@request.auth.id != "" || @request.data.email ~ "@yourdomain.com"
```

## Security Checklist

- [ ] PocketBase bound to `127.0.0.1` only (not exposed to public internet directly)
- [ ] Nginx handles all public traffic with SSL
- [ ] Admin credentials set via environment variables, not hardcoded
- [ ] SSL certificate installed and auto-renewing
- [ ] Firewall configured: only ports 22, 80, 443 open
- [ ] Daily database backups running
- [ ] PocketBase access rules on `card_progress` verified (users can only access own records)

```bash
# UFW firewall setup
sudo ufw allow ssh
sudo ufw allow 'Nginx Full'
sudo ufw enable
```
