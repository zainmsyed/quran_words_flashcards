## Findings

### Finding 1
- Severity: High
- Category: workflow (repo bloat) / dead-code
- Summary: Very large raster asset committed to repo: public/images/auth-background.png (~6.9 MB). This file is unused by the app (we use minified SVG and webp) and significantly increases repository size.
- Evidence:
  - public/images contains:
    - auth-background.png — 6,888,142 bytes (added earlier)
    - auth-background.min.svg, auth-background.webp, auth-background.svg
  - `ls -la public/images` output (repo): large PNG listed alongside optimized assets.
- Recommendation:
  - Remove the large PNG from the active branch (git rm public/images/auth-background.png && commit). If historical size is a concern, consider rewriting history or moving the large asset to an archival branch instead of the mainline to shrink repo size.
  - Add a CI/pre-commit guard to prevent committing binary assets above a threshold (e.g., 250 KB) or require LFS for large assets.
- Rule candidate: Yes — add a pre-commit check to prevent committing files larger than a configured threshold (e.g., 250 KB).


### Finding 2
- Severity: Medium
- Category: simplification / visual stability
- Summary: Brand glyphs in SVG assets are authored as <text> elements (e.g., public/images/favicon.svg and the large auth background string in src/ui/auth-background-svg.ts). Using <text> in brand SVGs can produce inconsistent rendering across platforms (favicon rendering, font substitution) and cause layout/visual instability.
- Evidence:
  - public/images/favicon.svg contains a <text> node with the Arabic alef glyph (file: public/images/favicon.svg).
  - src/ui/auth-background-svg.ts includes a large inline SVG string that contains <text> usage.
- Recommendation:
  - Convert the brand glyphs (aleph/alif mark) to outlined vector paths in the SVGs (outline the glyph in an editor such as Inkscape or by exporting a path). Replace the <text> nodes with <path> data to guarantee pixel-identical rendering across platforms and in favicons.
  - Regenerate PNG/ICO fallbacks from the outlined SVG.
- Rule candidate: Yes — brand SVGs used as favicons or UX brand marks must use outlined glyph paths (no <text> nodes).


### Finding 3
- Severity: Low
- Category: dead-code
- Summary: CSS selectors referencing `.brand-glyph` persist in app.css, but no markup uses that class anywhere in the repository. This is dead (unused) CSS and should be removed (or retained only if future markup will use it).
- Evidence:
  - `src/app.css` contains `.brand-mark .brand-glyph` and `.auth-brand .brand-glyph` rules.
  - Repository search for `brand-glyph` returns only CSS occurrences; no HTML/Svelte uses were found.
- Recommendation:
  - Remove the `.brand-glyph` CSS rules from src/app.css, or reintroduce the class in markup if text glyphs are intentionally used. Prefer removal since brand images have been switched to an <img> and glyphs should be outlined paths.
- Rule candidate: — (not proposed as a cross-project rule; this is repo-specific cleanup)


### Finding 4
- Severity: Medium
- Category: test-gap
- Summary: There are no UI/component tests covering the most visible, user-facing regressions introduced by this story (card flip containment, topbar alignment, TTS control placement). The existing automated tests cover core logic (SRS, session, pocketbase helpers) but no component or e2e checks exist to catch visual regressions.
- Evidence:
  - Tests executed via `npm test` exercise core helpers (summarizeStudyProgress, applyRatingToCard, recordStudy, buildSessionPlan, pocketbase helpers) — all passing.
  - No test files or task in repository exercise Card flip behavior or topbar alignment.
- Recommendation:
  - Add at least one UI/integration test (Playwright, Cypress, or Puppeteer) that executes a desktop-width session flow and asserts:
    1) flipping a card does not trigger a document vertical scroll (no mid-flip scrollbar), and
    2) AppTopbar renders and both session + settings instances have the same left-aligned brand position (pixel tolerance or visual snapshot).
  - Consider adding a component-level unit test (Svelte Testing Library) to assert the `.flashcard` toggles `.flipped` and the `.flashcard-scene` `clientHeight` remains stable.
- Rule candidate: Yes — critical visual flows (card flips, header alignment) should have at least one automated smoke or e2e test.


### Finding 5
- Severity: Low
- Category: simplification
- Summary: Multiple versions of the same auth/background asset are stored (non-minified SVG, minified SVG, webp, PNG). Consolidation would reduce repo noise and make the asset pipeline clearer.
- Evidence:
  - public/images contains auth-background.svg, auth-background.min.svg, auth-background.webp and auth-background.png.
- Recommendation:
  - Keep the minified SVG and the optimized webp as the canonical sources used by the app; remove or archive the non-minified SVG and any redundant raster copies. Add an image optimization step to CI (svgo + imagemin) to ensure future contributors add optimized assets.
- Rule candidate: Yes — require committed image assets to be optimized/minified and add CI checks for large/unoptimized images.
