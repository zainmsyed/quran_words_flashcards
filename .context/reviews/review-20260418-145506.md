## Findings
### Finding 1
- Severity: medium
- Category: bug
- Summary: The checked-in deployment example binds PocketBase to `127.0.0.1` inside the container, which breaks the Compose/Coolify topology because the web container proxies to `pocketbase:8090` on the internal network.
- Evidence:
  - `.env.example:5-11` labels `POCKETBASE_BIND=127.0.0.1:8090` as part of the Coolify + Docker Compose deployment settings.
  - `docker-compose.yml:20-35` forwards `POCKETBASE_BIND` into the `pocketbase` service, while the `web` service proxies `/api/` and `/_/` to `http://pocketbase:8090`.
  - `Dockerfile:108-121` passes `POCKETBASE_BIND` straight into `pocketbase serve`, so a loopback bind inside the container prevents the peer service from connecting.
  - `docs/coolify-setup.md:24-27` says the runtime container should use `POCKETBASE_BIND=0.0.0.0:8090`, so the example file and docs disagree on the deployable default.
  - `PB_ADMIN_EMAIL=test@example.com PB_ADMIN_PASSWORD=secret POCKETBASE_BIND=127.0.0.1:8090 docker compose config` resolves the compose environment to the loopback bind, confirming the mismatch is not just documentation noise.
- Recommendation: Change the deployment example to `POCKETBASE_BIND=0.0.0.0:8090` for the containerized path, and if a host-local bind is still needed for manual dev, separate that into a dev-only example or explicitly document it as non-Coolify.
- Rule candidate: When a container is reached by peer services, default it to `0.0.0.0` inside the container; reserve `127.0.0.1` for host-local process managers only.

### Finding 2
- Severity: medium
- Category: test-gap
- Summary: Story 017 only verifies static config/build output, so there is no automated check that the web container can actually reach PocketBase over the Compose network and catch the bind mismatch above.
- Evidence:
  - `story-017.md:11-12` says verification is limited to `docker compose config` plus the two image builds, then a manual check that the Compose topology looks private.
  - `scripts/pocketbase-smoke-test.mjs:121-220` starts PocketBase directly with a standalone temp data directory and exercises auth/persistence against `http://127.0.0.1:8099`; it does not start the Docker Compose stack or test the web-to-PocketBase network path.
  - `scripts/run-tests.mjs:133-475` covers core logic, auth helpers, and standalone PocketBase smoke helpers, but there is no compose-level integration test that would prove `http://pocketbase:8090/api/health` is reachable from the web service.
- Recommendation: Add a lightweight compose smoke check that starts both services and verifies the internal service-to-service path from the web container to PocketBase, so future bind or routing regressions fail automatically.
- Rule candidate: When deployment correctness depends on container networking, test the network path itself instead of relying only on static config or image builds.
