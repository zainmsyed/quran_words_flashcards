## Findings

### Finding 1
- Severity: Medium
- Category: bug
- Summary: The 520px mobile media query resets the session header padding and drops the safe-area inset, so notched phones can still clip the top bar.
- Evidence:
  - `src/app.css:579-593` sets `.app-topbar { padding: 0.9rem; }` for widths ≤720px.
  - `src/app.css:595-598` then overrides `.session-header` with `padding: 0.9rem var(--session-gutter, 1.1rem);` for widths ≤520px.
  - `src/ui/components/AppTopbar.svelte` uses both classes on the same header (`class="app-topbar session-header"`), so the later shorthand wins on the smallest phones and removes the `env(safe-area-inset-top)` offset that was added earlier in the broader media query.
- Recommendation:
  - Remove the 520px shorthand or restate the safe-area top padding there so the top bar keeps the notch offset on the smallest devices.
- Rule candidate: When a mobile top bar looks clipped, restore the header’s own padding/safe-area inset instead of changing viewport-level spacing so the rest of the screen stays put.

### Finding 2
- Severity: Medium
- Category: bug
- Summary: Audio-only browsers still show the pronunciation UI, but most cards and the Voice sample can be silent because the fallback only works when Web Speech is also available or a bundled MP3 exists.
- Evidence:
  - `src/core/tts-adapter.ts:21-30` reports support when either `speechSynthesis` or `Audio` exists.
  - `src/core/tts-adapter.ts:255-263` returns early if `tryPlayBundledAudio()` fails and `hasSpeechSupport()` is false.
  - `src/ui/VoiceSettings.svelte:55-59` calls `speak()` with no `audioSources`, so the sample has no bundled fallback at all.
  - `public/audio/` currently contains 10 MP3s (`w1.mp3`–`w10.mp3`), while `src/data/seed-words.json` contains 300 seed entries, so the majority of cards have no local audio file to fall back to.
- Recommendation:
  - Either require Web Speech support before exposing the pronunciation UI, or guarantee a bundled audio path for every sampled utterance / deck word so the control never goes silent on audio-only browsers.
- Rule candidate: When TTS fallback depends on speech synthesis, do not advertise audio-only support unless every path has a bundled audio file or another audible fallback.

### Finding 3
- Severity: Medium
- Category: bug
- Summary: The shared storage adapter does not guard localStorage writes/removals, so auth sign-in/sign-out can throw in browsers where storage access is blocked or quota-limited.
- Evidence:
  - `src/core/storage-adapter.ts:16-20` calls `localStorage.setItem()` / `removeItem()` without any try/catch, unlike `getItem()`.
  - `src/core/pocketbase-auth.ts:147-153` wraps those methods in `persistSession()` / `clearStoredSession()` without additional guarding.
  - `src/core/pocketbase-auth.ts:221-227` awaits `persistSession(session)` during sign-in and `clearStoredSession()` during sign-out, so a storage exception bubbles out after a successful PocketBase response.
- Recommendation:
  - Catch and downgrade storage write/remove failures in the adapter or auth helpers so login/logout still complete when persistence is unavailable; surface a non-blocking warning instead of rejecting the flow.
- Rule candidate: When localStorage is part of auth/session persistence, catch storage writes/removals the same way reads are caught so storage-restricted browsers degrade gracefully.
