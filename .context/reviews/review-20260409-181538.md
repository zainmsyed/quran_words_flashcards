## Findings
### Finding 1
- Severity: high
- Category: bug
- Summary: The custom footer can render wider than the terminal because the assembled line is never truncated to `width`.
- Evidence: `alignFooterLine()` only compares `visibleLength(left) + rightLength` and then either pads or concatenates `left + " · " + right`; it never clamps the final string. `sessionFooterLine()` returns that string directly to the footer renderer, so long model/branch/story labels or a narrow terminal can overflow the TUI.
- Recommendation: Clamp the final footer line with `truncateToWidth`/`visibleWidth` (or split the footer into shorter rows) before returning it, and add a narrow-terminal smoke test for the footer renderer.
- Rule candidate: —

### Finding 2
- Severity: medium
- Category: regression
- Summary: The new session banner is never mounted, so `ensureSessionChromeMounted()` blanks the header and leaves the top chrome empty.
- Evidence: `ensureSessionBannerMounted()` is defined, but no caller invokes it. - Recommendation: Either call `ensureSessionBannerMounted()` from the session mount path or restore the built-in header with `setHeader(undefined)` until the banner is ready.
