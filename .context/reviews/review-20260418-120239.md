## Findings

### Finding 1
- **Severity:** medium
- **Category:** bug
- **Summary:** `settingsInitialTab` in `App.svelte` is never reset to `'stats'` after the mastered overlay dispatches `openSettings({ tab: 'words' })`. Every subsequent tap on the topbar menu opens Settings to the Words tab instead of Stats, until the page is refreshed.
- **Evidence:** `src/App.svelte` line 16 — `settingsInitialTab` is only set on `on:openSettings` events and never reset on `on:close`. `src/ui/Settings.svelte` line 31 — `$: if (initialTab) tab = initialTab;` re-applies the persisted value every time the prop is re-evaluated.
- **Recommendation:** Reset `settingsInitialTab` to `'stats'` inside the `on:close` handler in `App.svelte`: `on:close={() => { currentPage = 'study'; settingsInitialTab = 'stats'; }}`. Alternatively use a one-shot prop pattern and clear `initialTab` after it has been applied.
- **Rule candidate:** When a component prop is used to imperatively set initial state, reset it at the call-site after the navigation completes so it does not persist as stale intent.

### Finding 2
- **Severity:** medium
- **Category:** bug
- **Summary:** The confetti `setTimeout` (7 600 ms) is not stored and cleared on component destroy. When the user taps "Review words" and navigates to Settings before the timer fires, the callback tries to write reactive state on a destroyed component instance.
- **Evidence:** `src/ui/StudySession.svelte` lines 316–322 — `confettiActive` and `confettiPieces` are written inside a bare `setTimeout` with no `clearTimeout` companion. No `onDestroy` import or cleanup block exists. `App.svelte` uses `{:else if}/{:else}` so `StudySession` is destroyed when Settings opens.
- **Recommendation:** Store the timer id and cancel it in `onDestroy`:
  ```ts
  import { onMount, onDestroy } from 'svelte';
  let confettiTimer: ReturnType<typeof setTimeout> | null = null;
  // inside the reactive block:
  confettiTimer = setTimeout(() => { confettiPieces = []; confettiActive = false; confettiTimer = null; }, 7600);
  onDestroy(() => { if (confettiTimer) clearTimeout(confettiTimer); });
  ```
- **Rule candidate:** Always clear timers and subscriptions in `onDestroy` when they mutate component-local reactive state.

### Finding 3
- **Severity:** low
- **Category:** bug / semantic inconsistency
- **Summary:** Mastered words (easyCount ≥ 3) are still selected as review cards by the session planner if their `dueDate ≤ now`, and they are still counted in `dueCount` in Stats. This contradicts the user-visible concept of "mastered" — a mastered word reappears in review queues and clutters the "Due today" stat.
- **Evidence:** `src/core/session.ts` line 132 — `dueAll` filter uses only `interval > 0 && dueDate <= now`; no easyCount exclusion. `src/core/progress-summary.ts` line 38 — `dueCount` uses the same predicate. A card with easyCount = 4 and dueDate = yesterday will appear in both `dueCount` and the review queue.
- **Recommendation:** Decide and document the intended policy. If mastered words should not be re-queued until explicitly requested, exclude them from `dueAll` in `buildSessionPlan` and from `dueCount` in `summarizeStudyProgress`: `const isNotMastered = (state?.easyCount ?? 0) < MASTERED_EASY_COUNT;`. Import and apply `MASTERED_EASY_COUNT` in both files.
- **Rule candidate:** When a mastery threshold is introduced, audit every place that selects "due" or "review" cards and decide explicitly whether mastered cards should be included.

### Finding 8
- **Severity:** low
- **Category:** bug / accessibility
- **Summary:** The mastered overlay uses `role="dialog"` combined with `aria-live="polite"`, lacks `aria-modal="true"`, and has no focus trap. Users navigating by keyboard cannot dismiss the overlay and focus is not moved into it when it appears.
- **Evidence:** `src/ui/StudySession.svelte` line 378 — `role="dialog" aria-live="polite"`. `aria-live` is semantically inappropriate on a `role="dialog"` element; dialogs rely on focus management, not live regions. No `aria-modal` attribute. No `tabindex` on the content div. No focus-trap logic.
- **Recommendation:** Remove `aria-live="polite"` from the overlay (it conflicts with `role="dialog"`). Add `aria-modal="true"`. On mount of the overlay, move focus to the first action button. On unmount, restore focus to the previously focused element. Until a full focus-trap is implemented, at minimum add `tabindex="-1"` and `autofocus` on the primary button.
- **Rule candidate:** When a full-screen Svelte overlay uses `role="dialog"`, it must include `aria-modal="true"` and shift focus to the dialog on open.

### Finding 11
- **Severity:** info
- **Category:** simplification
- **Summary:** `FALLBACK_BASE_URL` in `pocketbase-auth.ts` is hardcoded to `http://127.0.0.1:8090`. In production (when `window.location.origin` is available), the fallback is never reached. But in SSR or test environments where `window` is undefined and no `VITE_POCKETBASE_URL` env var is set, requests would hit localhost — potentially confusing in CI.
- **Evidence:** `src/core/pocketbase-auth.ts` line 4.
- **Recommendation:** Document the precedence order in a comment (`VITE_POCKETBASE_URL` → `window.location.origin` → localhost fallback) so future maintainers understand why the hardcoded fallback is intentional for local dev.
