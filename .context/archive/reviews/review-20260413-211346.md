## Findings

### Finding 1
- Severity: Medium
- Category: simplification
- Summary: The favicon’s Arabic alif is still authored as a `<text>` node in `public/images/favicon.svg`, which can render inconsistently across browsers and platforms.
- Evidence:
  - `public/images/favicon.svg` contains an embedded `<text>` element for the glyph (`<text ...>ا</text>`).
  - The same asset is used as the in-app brand mark and as the favicon fallback, so any font-substitution mismatch affects multiple surfaces.
- Recommendation:
  - Convert the alif glyph to an outlined SVG `<path>` so the favicon and brand mark render identically across platforms.
  - Regenerate the PNG/ICO fallbacks from the outlined SVG after conversion.
- Rule candidate: Yes — brand SVGs used for favicons or in-app marks should use outlined glyph paths instead of `<text>`.

### Finding 2
- Severity: Medium
- Category: test-gap
- Summary: The story introduced desktop-only flip containment and topbar alignment changes, but there is still no automated UI/e2e coverage for these regressions in the current branch.
- Evidence:
  - `npm test` only exercises Node/core helpers (`summarizeStudyProgress`, `applyRatingToCard`, PocketBase helpers, etc.); it does not cover Card flip behavior or header alignment.
  - The repo currently has no Playwright/Cypress/Puppeteer test suite to assert the desktop scroll/overflow behavior or compare topbar alignment between session and settings.
- Recommendation:
  - Add at least one UI smoke test at desktop viewport that flips a card and asserts `window.scrollY` stays stable while the flip animates.
  - Add a second assertion (same test or another) that verifies session/settings topbar brand alignment stays within a small tolerance.
- Rule candidate: Yes — visible desktop UI regressions should have at least one automated smoke/e2e test.
